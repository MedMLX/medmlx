Export, profile and tune MedMLX Apple runtimes

Run these commands from the conversion/ directory of the repository. This procedure compares the same original checkpoint, synthetic input tensors and FP32 outputs under explicit runtime policies. It applies to an exported network or component. Whole-volume segmentation, diffusion sampling and language generation require additional pipeline tests.

1. Export and preserve a replayable workload

make env
bash environment/setup.sh --run python recipes/flexible_unet/export.py

Replace flexible_unet with the maintained recipe directory for another model. To re-export and test every maintained recipe, run make qualify; make qa runs only lint and strict Pyright. Preserve the log. The coverage table lists component limits and models that still need a recipe or complete pipeline qualification.

A recipe now writes .aimodel, .mlpackage, .verification.json and .runtime.npz beside one another under ignored build/. The fixture contains schema_version=1, input/<name> and output/<name> arrays. Outputs come from the source model, before either conversion. Integer inputs are stored as int32, matching both Apple runtime interfaces. Floating-point inputs remain FP32.

The benchmark refuses a failed export receipt, unknown schemas, changed input shape or dtype, nonfinite inputs and a mismatched output dtype. It checks every first, warm-up and timed output against the source fixture using the recipe's existing tolerance and PSNR policy. The separate Core AI profiling call is also checked. A failure stops the run, retains its phase and one-based iteration, and exits nonzero. A failed run cannot support a speed comparison. Do not relax a tolerance to make a candidate pass. Fixtures can be large; keep them in build/ and regenerate them when the checkpoint or recipe changes.

2. Measure the default runtime and its stages

bash environment/setup.sh --run env USE_OS_COREAI=1 \
  python -m medmlx_convert.runtime_benchmark \
  build/flexible_unet/flexible_unet_endoscopic \
  build/flexible_unet/flexible_unet_endoscopic.runtime.npz \
  coreai-default build/runtime-tuning/flexible-coreai-default.json --inspect

bash environment/setup.sh --run python -m medmlx_convert.runtime_benchmark \
  build/flexible_unet/flexible_unet_endoscopic \
  build/flexible_unet/flexible_unet_endoscopic.runtime.npz \
  coreml-all build/runtime-tuning/flexible-coreml-all.json --inspect

Unset USE_LOCAL_COREAI before running Core AI. The CLI verifies that OS specialization is supported and fails if it is unavailable. Each run uses one fresh process, a first call, three further warmups and ten completed timed calls. --runs and --warmup override those counts.

Recorded stageMeaning
load_sLoad and function setup. OS/filesystem caches remain intact; this is not a guaranteed cold-cache measurement.
reused_input_setup_sOne-time preparation for reusable input profiles, reported separately from warm calls.
prepare_sCore AI input-array construction. Core ML uses the existing NumPy inputs and reports zero for this separate Python stage.
execute_sAwaited Core AI invocation or completed Core ML prediction. Includes runtime work and any internal transfers; it is not pure GPU time.
materialize_sExpose completed host arrays. Core ML may already materialize them inside predict, so stage boundaries differ.
total_sCompleted call across the declared boundary. Use this value when comparing matching call scopes.

Run JSON uses schema_version=4, including the declared build_profile for FP32 or FP16. Its calls list retains each call's phase, one-based iteration, timing, per-output comparisons and verdict. When requested, the Core AI profiling call is appended with phase=inspection; its failure also fails the run's final verdict. Malformed or nonfinite outputs retain an error message. The top-level verdict fails at the first bad call; later calls are not executed. Comparisons run between inference timing intervals, so use the same checking protocol across runtimes. Package versions, load averages and process peak RSS are also recorded. RSS includes the Python process, fixtures and outputs; it is not accelerator-only memory.

3. Screen one runtime change at a time

Use the same command with one of these profile names. The output filename must be unique for each profile and pass.

ProfileExact policy
coreml-allAll compute units, default specialization.
coreml-fastAll compute units, FastPrediction specialization hint.
coreml-gpuCPU and GPU allowed; Neural Engine excluded.
coreml-neCPU and Neural Engine allowed; GPU excluded.
coreai-defaultOS Core AI default specialization, fresh bytes-backed inputs.
coreai-gpuGPU preferred; other supported units remain allowed.
coreai-neNeural Engine preferred; other supported units remain allowed.
coreai-reuse-bytesDefault specialization, reuse bytes-backed input arrays.
coreai-reuse-metalDefault specialization, reuse Metal-backed input arrays.
coreai-reuse-iosurfaceDefault specialization, reuse IOSurface-backed input arrays.
Reusable-input profiles measure repeated inference on the same prepared tensors. Their one-time input construction is excluded from warm calls. Report this as a separate prepared-input lane. For a new image or patch, prepare its own inputs and account for that preparation. Never reuse an old image buffer as though it represented a new request. The original host-to-host table includes input preparation and must retain that boundary.

Runtime profiles preserve the artifact's admitted build precision. FP16, quantization, changed tensor shapes and larger batches require separate exports and output qualification. Model instances already persist across warm calls; reloading a model for every patch would add an avoidable application cost.

4. Confirm candidates in reverse order

After a short screen, compare the baseline and candidate in two passes: baseline then candidate, followed by candidate then baseline. Keep ten timed calls per run. Execute sequentially so the runtimes do not contend with one another. Preserve all four JSON files and their logs. Repeat for each model; do not infer a universal setting from one architecture.

Check matching inputs, shapes, checkpoint, precision, machine and call scope. Require every output decision to pass. Examine the ranges of per-pass medians and the raw sample distribution. Treat small, inconsistent or overlapping changes as inconclusive. Shared-machine runs are diagnostic; do not stop another user's process to improve a benchmark.

5. Inspect placement and loading separately

--inspect collects diagnostics after the timed calls. Core AI records native profiler events for a separate invocation. Core ML records its compute plan's anticipated device and estimated cost for each top-level operation. Unknown plan entries remain unknown. A preference, compute-unit policy or compute plan does not prove actual ANE utilization or energy consumption.

To capture native execution in Instruments, first check the installed CLI and available templates:

xcrun xctrace list templates
xcrun xctrace record --template 'Core AI' \
  --output build/runtime-tuning/coreai.trace --time-limit 30s \
  --env USE_OS_COREAI=1 --launch -- \
  <path-to-conda-env>/bin/python \
  -m medmlx_convert.runtime_benchmark \
  build/flexible_unet/flexible_unet_endoscopic \
  build/flexible_unet/flexible_unet_endoscopic.runtime.npz \
  coreai-default build/runtime-tuning/instrumented.json
xcrun xctrace export --input build/runtime-tuning/coreai.trace --toc

Replace <path-to-conda-env>/bin/python with the interpreter of the medmlx-conversion environment created by make env; bash environment/setup.sh --run python -c 'import sys; print(sys.executable)' prints it. Keep instrumented timings out of the acceptance comparison. If capture fails or requires unavailable permissions, retain the error and mark hardware placement unverified.

For Core ML startup, Apple's supported approach is to keep a compiled .mlmodelc at a stable path and load it with coremltools.models.CompiledMLModel. The path comes from MLModel.get_compiled_model_path(). Refresh the compiled asset when the source package changes. The warm policy sweep here loads .mlpackage; it does not claim a measured stable-cache startup improvement.

6. Preserve the surrounding algorithm

Segmentation: keep image normalization, patch size, overlap, window blending, label mapping, affine and postprocessing fixed. Benchmark both one patch and the whole volume before changing application routing.

Diffusion: export the source components, then port the complete sampling loop. Preserve the exact timestep sequence, beta/alpha values, scheduler arithmetic, step count, eta, guidance, initial noise and noise drawn at each step. Replay the same draws across runtimes. Check intermediate latents and final decoded outputs. LesionDiffusion's current MLX sampler explicitly preserves the upstream rounded schedule; a new backend must preserve that contract.

Language models: preserve tokenization, prompt formatting, sampling parameters and cache semantics. Check prefill, cache updates and multi-token decoding before reporting tokens per second. A vision-encoder export is not complete generation.

Rejected shortcuts: changing diffusion steps or scheduler to make one backend faster changes the workload; lowering precision without a new output check can change logits; silently substituting a backend hides failures; claiming ANE execution from an allowed-device setting is unsupported; ranking SwinUNETR across its currently different MLX and MONAI patch-merging graphs violates the matching-output requirement.

7. Compare the actual MLX ports with both native formats

Install the lock-pinned environment, which includes MLX:

make env

bash environment/setup.sh --run python -m medmlx_convert.runtime_benchmark \
  build/flexible_unet/flexible_unet_endoscopic \
  build/flexible_unet/flexible_unet_endoscopic.runtime.npz \
  mlx-gpu build/runtime-tuning/flexible-mlx.json \
  --mlx-root .. --warmup 3 --runs 10

Run from a quiet host after other model jobs finish. Use the same saved fixture with the native profiles in Section 2, keeping a separate output file for each profile and pass. Follow the reverse-order comparison in Section 4. The supported ports are FlexibleUNet endoscopy, renal SegResNet, nnU-Net liver, SynthSeg v1 and automatic VISTA3D. The explicit checkout root must contain their owning packages and medmlx-core. Source checkout revisions and dirty state are recorded; the native report supplies the checkpoint path and pinned source revision used to load MLX. These adapters reject FP16 builds because their current MLX execution is FP32.

nnU-Net follows its owning native runner's qualified compilation default; the other ports use their owning model calls without an external compile wrapper.

The runtime checks every completed call outside its timing interval. Keep the checkpoint and source checkout fixed across passes. A dirty flag does not identify individual uncommitted edits. Per-process medians and p95 values describe these samples; they are not confidence intervals across independent machines.

Compare total_s: host input through completed host output, including required layout conversion, transfer and materialization. MLX is explicitly evaluated and synchronized. Loading and process peak RSS remain diagnostics: MLX weight conversion loads the upstream checkpoint, while native runtimes load saved assets, so these setup peaks do not measure comparable resident-model memory.

Rejected comparisons: SynthSeg probabilities versus exported logits compare different outputs; use its shared public logits() path. VISTA3D's fixed-class embedding cache removes work performed by the native graph; supply class IDs on every MLX invocation. Checking only the last result can hide an intermittent failure; every call must pass.

Historical evidence and API references

The following October 13 experiments retain their original failures and scope. They are not current paired timing results. Current build qualification and the required QA gate are reported in the README.

The 2026-10-13 sweep confirmed no consistent improvement that met the matched comparison rule, so it does not justify changing the default runtime policies. Core AI SegResNet default and NE-preferred first calls failed in one pass with max absolute errors of 31.71 and 32.25 against tolerance 0.01, then passed in the reverse pass. A separate 20-call buffer-owner diagnostic did not reproduce the error; its cause remains unverified. Exclude those paths from speed recommendations until the first-call failure is resolved. VISTA3D's Core ML CPU_AND_NE screen hit a 180-second limit. Keep failures in the experiment record.

The October 13 QA run recorded 23 passed and 2 failed. One failure was a recipe being removed by a concurrent change after pytest collected it. SAM 3 failed Core ML mask and semantic outputs (19.6 and 1.22 against 0.1 and 0.01); its Core AI outputs passed. The gate is not green. See the SAM 3 failure receipt. The coverage docs also retain a separate Lung Nodule Core AI failure. Earlier passes and successful diagnostic retries do not erase these failures.

A separate saved-package SAM 3 diagnostic passed three Core ML calls under ALL and three under CPU_AND_GPU, including checking the retained first output before and after a Core AI invocation. Mask error was 0.0503 and semantic error 0.000174. The export-time failure was not reproduced and its cause remains unverified.
